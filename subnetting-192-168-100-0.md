# Packet Tracer: Subnet 192.168.100.0/24 and Configure the Network

A write-up of how I subnetted `192.168.100.0/24` for a two-router topology, built the addressing table, and then configured R1, S3, and PC4 in Cisco Packet Tracer.

## Part 1: Design the addressing scheme

### Step 1: Subnet the network

**a. How many subnets are needed?**
**5.** Four LANs (two on R1, two on R2) plus one WAN link between R1 and R2.

**b. How many bits must be borrowed?**
**3 bits.** Two bits only give 4 subnets (2² = 4), which isn't enough. Three bits give 8 subnets (2³ = 8).

**c. How many subnets does this create?**
**8** (2³).

**d. How many usable hosts per subnet?**
**30.** That leaves 5 host bits, so 2⁵ - 2 = 30, which covers the 25 hosts required. Borrowing a fourth bit would drop it to 14 hosts, which is too few.

**e. Binary value of the first five subnets**

The three borrowed bits are bits 7, 6, and 5 of the fourth octet.

| Subnet | Network Address | Bit 7 | Bit 6 | Bit 5 | Bit 4 | Bit 3 | Bit 2 | Bit 1 | Bit 0 |
|---|---|---|---|---|---|---|---|---|---|
| 0 | 192.168.100. | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 1 | 192.168.100. | 0 | 0 | 1 | 0 | 0 | 0 | 0 | 0 |
| 2 | 192.168.100. | 0 | 1 | 0 | 0 | 0 | 0 | 0 | 0 |
| 3 | 192.168.100. | 0 | 1 | 1 | 0 | 0 | 0 | 0 | 0 |
| 4 | 192.168.100. | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |

**f. New subnet mask**

| First Octet | Second Octet | Third Octet | Fourth Octet |
|---|---|---|---|
| 11111111 | 11111111 | 11111111 | 11100000 |

| First Decimal | Second Decimal | Third Decimal | Fourth Decimal |
|---|---|---|---|
| 255 | 255 | 255 | **224** |

The mask is `255.255.255.224`, or `/27`.

**g. Subnet table**

Each subnet has a block size of 32 addresses.

| Subnet | Subnet Address | First Usable | Last Usable | Broadcast |
|---|---|---|---|---|
| 0 | 192.168.100.0 | 192.168.100.1 | 192.168.100.30 | 192.168.100.31 |
| 1 | 192.168.100.32 | 192.168.100.33 | 192.168.100.62 | 192.168.100.63 |
| 2 | 192.168.100.64 | 192.168.100.65 | 192.168.100.94 | 192.168.100.95 |
| 3 | 192.168.100.96 | 192.168.100.97 | 192.168.100.126 | 192.168.100.127 |
| 4 | 192.168.100.128 | 192.168.100.129 | 192.168.100.158 | 192.168.100.159 |
| 5 | 192.168.100.160 | 192.168.100.161 | 192.168.100.190 | 192.168.100.191 |
| 6 | 192.168.100.192 | 192.168.100.193 | 192.168.100.222 | 192.168.100.223 |
| 7 | 192.168.100.224 | 192.168.100.225 | 192.168.100.254 | 192.168.100.255 |

Rows 8 to 10 in the lab's table stay blank because only 8 subnets exist. I only needed subnets 0 to 4, so 5 to 7 are left unused for growth.

### Step 2: Assign subnets to the topology

| Subnet | Assigned to |
|---|---|
| 0 | LAN on R1 G0/0 |
| 1 | LAN on R1 G0/1 |
| 2 | LAN on R2 G0/0 |
| 3 | LAN on R2 G0/1 |
| 4 | WAN link between R1 and R2 |

### Step 3: Addressing table

I followed the lab's rules: routers get the first usable address (R2 gets the last usable on the WAN), switches get the second usable, and PCs get the last usable.

| Subnet | Router interface | Switch (VLAN 1) | PC |
|---|---|---|---|
| 0 (R1 G0/0 LAN) | R1: 192.168.100.1 | 192.168.100.2 | 192.168.100.30 |
| 1 (R1 G0/1 LAN) | R1: 192.168.100.33 | 192.168.100.34 | 192.168.100.62 |
| 2 (R2 G0/0 LAN) | R2: 192.168.100.65 | 192.168.100.66 | 192.168.100.94 |
| 3 (R2 G0/1 LAN) | R2: 192.168.100.97 | 192.168.100.98 | 192.168.100.126 |
| 4 (WAN) | R1: 192.168.100.129 | n/a | n/a |
| 4 (WAN) | R2: 192.168.100.158 | n/a | n/a |

All devices use mask `255.255.255.224`. Each switch's default gateway is its router's address, and each PC's default gateway is also its router's address.

> **Note:** S3 and PC4 take the switch and PC addresses for whichever LAN they sit on in your topology. Match them to the row above for that LAN.

## Part 2: Configure devices and verify connectivity

EIGRP was already configured between R1 and R2, so I only needed to finish the addressing.

### Step 1: Configure R1's LAN interfaces

```text
R1> enable
R1# configure terminal
R1(config)# interface g0/0
R1(config-if)# ip address 192.168.100.1 255.255.255.224
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface g0/1
R1(config-if)# ip address 192.168.100.33 255.255.255.224
R1(config-if)# no shutdown
R1(config-if)# end
R1# copy running-config startup-config
```

The `no shutdown` command brings each interface up so the hosts can reach their default gateway.

### Step 2: Configure S3

I gave the VLAN 1 interface its address and set the default gateway. Replace the placeholders with the S3 row from the addressing table.

```text
S3> enable
S3# configure terminal
S3(config)# interface vlan 1
S3(config-if)# ip address <S3 address> 255.255.255.224
S3(config-if)# no shutdown
S3(config-if)# exit
S3(config)# ip default-gateway <router address on that LAN>
S3(config)# end
S3# copy running-config startup-config
```

### Step 3: Configure PC4

On PC4 I opened **Desktop > IP Configuration**, chose **Static**, and entered:

| Field | Value |
|---|---|
| IP Address | `192.168.100.254` (the last usable address on its subnet) |
| Subnet Mask | 255.255.255.224 |
| Default Gateway | `192.168.100.1` |

### Step 4: Verify connectivity

From R1, S3, and PC4, I pinged every address in the addressing table:

```text
R1# ping 192.168.100.158
```

All pings succeeded, which confirmed the addressing and the EIGRP routes were working across both routers.

## What I took away

- Count the subnets first, then borrow the fewest bits that give enough subnets without dropping below the host requirement.
- Block size is 256 minus the mask value in the last octet (256 - 224 = 32), so subnets step by 32.
- Each subnet's broadcast address is the address just before the next subnet.
